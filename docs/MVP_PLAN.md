# SpeechOptimizer MVP 前置验证与 PRD 收敛计划

> 状态：待确认执行
> 计划日期：2026-08-31
> 执行角色：单人开发，后端工程师背景
> 当前目标：先完成可浏览的产品界面，再验证开源技术底座和本地技术链路，最后形成可开发的 PRD
> 当前边界：本文档是执行计划，不是最终 PRD；本轮只优化文档，不编写产品代码、不安装插件

## 1. 文档定位

本计划用于回答三个问题：

1. 在正式开发业务功能前，产品界面需要先验证什么。
2. 哪些免费开源项目值得作为建站模板或功能技术底座，以及改造成本是否可接受。
3. 如何在本地跑通依赖和核心技术链路，并将已验证结论沉淀为最终 PRD。

本计划不再直接承诺“4 周完成可收费 MVP”。在界面、开源底座、Waffo 能力和语音分析链路尚未验证前，生产上线周期不具备可靠估算基础。正式开发排期将在 PRD 定稿后给出。

## 2. 已确认约束

以下内容属于硬约束，后续阶段不得自行替换或绕过。

### 2.1 支付平台

- 支付平台暂时固定为 [Waffo](https://waffo.ai/)。
- 当前不设计 Stripe、Paddle 或其他支付平台的备用链路。
- 如果 Waffo 的 Sandbox、订阅、一次性支付、Webhook、退款或主体审核能力不满足要求，应将其记录为阻塞项并提交决策，不得擅自切换平台。
- 支付页面在界面阶段只展示模拟状态，不发起真实支付。

### 2.2 建站模板

- 暂不购买收费 SaaS 模板。
- 只评估许可证允许商业使用和二次改造的免费开源项目。
- [`nextjs/saas-starter`](https://github.com/nextjs/saas-starter) 作为建站模板的主要候选，但在完成代码、许可证和维护状态核查前不做最终选型。
- 改造结果应沉淀为自己的通用建站模板，供后续产品复用，而不是把 SpeechOptimizer 的业务逻辑直接固化进通用层。
- 开源项目只能缩短基础能力建设时间，不能反向扩大 MVP 范围。

### 2.3 本地优先

- 数据库、对象存储、缓存、队列、邮件捕获等依赖性组件或中间件，优先通过 Docker 服务在本地提供。
- 只启动实际需要的服务，不为了架构完整性一次性引入全部中间件。
- 本地链路通过验收后，再单独制定线上部署方案。
- 前置阶段不绑定 Vercel、Supabase、Trigger.dev 或其他托管平台。
- Waffo Sandbox、STT 和 LLM 等无法完全本地化的外部服务，作为明确例外单独记录调用、成本和数据边界。

### 2.4 GitHub 插件和开源项目调研

- 使用 GitHub 插件搜索和核查候选开源项目。
- 当前 GitHub 插件尚未安装，安装前必须获得用户明确确认。
- 插件安装完成前，不把任何未经实时核查的仓库信息写成调研结论。
- 调研完成后先提交候选清单、证据、改造工作量和难度，由用户决定是否采用；未经决策不进入改造。

### 2.5 界面优先和最终 PRD

- 第一项实现工作是产品界面，不依赖真实后端、数据库、AI 或支付即可在浏览器访问。
- 界面使用 Mock 数据覆盖核心流程、空状态、加载状态、失败状态和权限状态。
- 用户完成浏览器验收后，才进入开源底座选型和本地技术验证。
- 最终 PRD 必须吸收界面验收、开源项目调研和本地技术验证的结论，而不是在这些结论产生前提前定稿。

## 3. 产品假设

以下内容用于指导界面原型和技术调研，仍需通过界面验收和用户反馈确认。

### 3.1 目标用户

- 首个用户群：需要录制英语短视频、YouTube、播客或演讲内容的创作者。
- 产品只分析英语，允许英语母语和非母语用户使用。
- 第一版仅面向 18 岁及以上用户。
- 首个核心场景：用户录制或上传 30-120 秒内容，发现语速、口头禅、停顿、冗余和结构问题。

### 3.2 核心价值

SpeechOptimizer 是 AI 口头表达教练，不是泛语言学习工具，也不承诺消除口音。它帮助用户在下一次录制时说得更清楚、更自然、更有节奏。

一句话价值主张：

> Record a short speech, get actionable feedback, and sound clearer on your next take.

核心闭环：

```text
录音或上传音频
  -> 查看分析进度
  -> 获得三条优先建议和客观指标
  -> 按建议重新录制
  -> 比较前后变化
```

### 3.3 暂定商业假设

以下数值仅用于界面占位和后续验证，不属于已确认定价：

- 匿名体验：1 次，最多 60 秒。
- Free：每月 5 分钟。
- Pro 月付：12 USD/月，每月 60 分钟。
- Pro 年付：96 USD/年。
- 充值包：30 分钟 6 USD；100 分钟 15 USD。
- 单次深度报告：4.99 USD。

界面必须让这些内容易于替换。PRD 定稿前需要确认是否同时保留订阅、充值包和单次报告，避免首版计费模型过多。

## 4. 总体执行路径

```text
阶段 1：产品界面设计与浏览器原型
  -> 门禁 A：用户确认信息架构、核心流程和视觉方向
  -> 阶段 2：确认安装 GitHub 插件并调研免费开源底座
  -> 门禁 B：用户选择复用候选或自建
  -> 阶段 3：Docker 本地环境与核心技术 Spike
  -> 门禁 C：本地链路、成本、隐私和 Waffo 能力结论可接受
  -> 阶段 4：形成最终 PRD
  -> 后续：基于 PRD 另行制定开发、测试和上线计划
```

原则：每个阶段只解决本阶段问题。任何门禁未通过，都先修正结论或范围，不提前推进后续实现。

## 5. 阶段 1：产品界面设计与浏览器原型

### 5.1 目标

在接入真实业务能力前，用可交互界面确认产品是否容易理解、核心闭环是否顺畅、首版页面是否足够，以及哪些状态需要后端支持。

### 5.2 实现边界

- 可以使用 Mock 数据、静态夹具和本地状态。
- 不接真实 Waffo，不产生订单或收费。
- 不接真实 STT、LLM、数据库、对象存储和邮件服务。
- 不要求登录服务可用，但需要展示匿名、未登录、已登录和无权限界面状态。
- 不为了原型提前确定数据库 Schema、API 形式或部署平台。
- 原型应能通过本地 URL 在浏览器访问，明确提供启动命令和访问地址。

### 5.3 第一批页面

#### 核心体验

- `/`：首页即工作台，直接开始录音或上传，不做纯营销落地页。
- `/analysis/demo-processing`：展示上传、排队、转写、分析和失败状态。
- `/analysis/demo-result`：展示核心指标、三条优先建议、证据和重录入口。
- `/compare/demo`：展示前后指标、建议变化和不可比较状态。

#### 账户与商业界面

- `/history`：展示历史任务、状态、时长、关键指标、空状态和删除入口。
- `/pricing`：展示暂定计费方案，并明确支付由 Waffo 承担。
- `/settings/billing`：展示订阅状态、分钟余额和流水。
- `/settings/privacy`：展示音频保存选择、记录删除和账户删除。
- `/contact`：展示产品反馈、账单支持和隐私请求的联系入口。
- 登录/注册弹层或页面：展示 Google OAuth 和邮箱 Magic Link 的预期体验。

#### 运营和合规占位

- `/admin`：展示最小管理后台的信息架构，不实现真实管理操作。
- `/privacy`、`/terms`、`/refund-policy`、`/data-deletion`：先完成页面结构和待补内容标记，不在法律文本未审核时伪装为正式条款。

### 5.4 必须覆盖的交互和状态

- 录音权限未请求、已允许、已拒绝和被撤销。
- 正在录音、暂停、完成、重新录制和放弃。
- 上传拖拽、格式错误、时长超限、大小超限和网络失败。
- 分析排队、处理中、完成、失败、取消和重试。
- 匿名体验已用尽、分钟不足、需要注册和需要购买。
- 无历史记录、存在处理中记录和记录删除确认。
- 前后样本可比较、无明显变化和不可比较。
- 桌面与移动端的核心流程。

### 5.5 设计原则

- 产品定位是高频工作工具，界面应克制、清晰、便于扫描，不采用营销页式的大面积装饰布局。
- 首页首屏直接呈现录音或上传主操作，产品能力必须是第一视觉信号。
- 结果页先显示最重要的三条行动建议，再展示辅助指标和细节。
- 所有指标都要解释其意义，不使用无法验证的心理、自信、人格或情绪判断。
- 删除、取消、重试、权限拒绝和支付失败等关键状态必须有明确反馈。
- 移动端触控区域、文本换行、录音控件和结果对比不得重叠或溢出。
- 第一版视觉候选为轻量、扁平、工具型设计，以清晰排版和语义色为主，避免重阴影、复杂渐变和无意义动画；具体品牌色和字体在原型阶段由用户确认。
- 正文在移动端不小于 16px，普通文本与背景对比度至少达到 4.5:1，不能只依靠颜色表达改善、失败或选中状态。
- 所有交互控件支持键盘操作和清晰的可见焦点；图标按钮具有可读名称，不使用只有 Hover 才能发现的关键操作。
- 移动端主要触控目标不小于 44×44px，相邻操作留出足够间距，录音主操作不得因动态文案改变尺寸。
- 长时间分析使用稳定的进度或骨架反馈，保持布局和焦点稳定，并让辅助技术能够感知忙碌和完成状态。
- 动效用于解释状态变化，支持减少动画偏好；录音或媒体内容不得自动播放。

### 5.6 门禁 A：界面验收

通过条件：

- 用户可以从首页完成“录制/上传 -> 等待 -> 查看结果 -> 重录 -> 比较”的模拟闭环。
- 用户能理解三条建议、指标、剩余分钟、数据保存策略和付费入口。
- 所有 P0 页面可以通过浏览器访问，无明显断链。
- 在 320、375、414、768、1024 和 1440px 宽度下，关键页面无内容遮挡、非预期横向滚动或操作区溢出。
- 仅使用键盘可以完成核心模拟闭环；焦点顺序、弹层焦点和错误提示可理解。
- 录音、上传、处理中、成功和失败状态不仅通过颜色区分，状态变化有可感知反馈。
- 用户已确认信息架构、核心交互和视觉方向，未决项已形成清单。

阶段交付物：

- 可访问的本地界面原型。
- 经用户确认的视觉方向、基础设计 Token 和核心组件清单。
- 页面和状态清单。
- 界面验收记录。
- 需要后端支持的能力清单。

## 6. 阶段 2：免费开源项目调研与选型

### 6.1 启动前提

1. 门禁 A 已通过。
2. 用户明确确认安装 GitHub 插件。
3. 插件安装完成并可访问 GitHub 仓库信息。

如果插件无法安装或无法使用，应停止 GitHub 插件调研并说明阻塞原因。除非用户另行授权，不使用其他搜索方式替代指定工具后再声称完成本阶段。

### 6.2 调研方向

#### A. 通用建站模板

- 以 `nextjs/saas-starter` 为主要候选。
- 补充搜索 2-4 个技术栈相近的免费开源 SaaS starter 作为对照。
- 重点核查认证、账户、后台、数据库迁移、权限、测试、Docker 本地开发和支付解耦程度。
- 不因候选内置 Stripe 就接受 Stripe；需要评估移除并改为 Waffo 的成本。

#### B. 录音和音频上传

- 搜索浏览器录音、音频波形、格式校验、断点或可恢复上传相关项目。
- 优先复用稳定组件，不直接复用带完整产品假设的复杂编辑器。
- 核查移动 Safari、Chrome、MediaRecorder 格式差异和许可证。

#### C. 语音分析技术底座

- 搜索逐词时间戳转写、口头禅检测、停顿检测、WPM、重复短语和转写置信度相关项目。
- 区分可以直接作为依赖的库、只能参考算法的项目和不适合商用的 Demo。
- AI 反馈部分只复用可验证的结构化处理能力，不照搬无法解释的评分体系。

#### D. 异步任务和本地基础设施

- 搜索与候选技术栈匹配、支持本地 Docker 的任务队列、对象存储和邮件捕获方案。
- 优先选择维护成本低、可观察、可重试且不强绑定单一云平台的组件。
- 若 starter 已包含相关能力，仍需确认是否能满足幂等、取消和失败恢复要求。

#### E. Waffo 接入参考

- 搜索官方或社区维护的 Waffo SDK、示例和 Webhook 实现。
- 只把来源、更新时间、支持事件和许可证可确认的项目列为候选。
- 如果没有可靠开源实现，应明确结论为“需要自行接入”，不得用其他支付平台示例冒充可直接复用。

### 6.3 候选项目报告格式

每个候选必须提供：

- 仓库名称、准确 URL、许可证和最近维护状态。
- 与当前需求匹配的可复用模块。
- 需要删除、替换和新增的部分。
- 与 Waffo、本地 Docker 和界面原型的兼容性。
- 测试、文档、安全、依赖和社区维护风险。
- 是否适合沉淀进通用建站模板。
- 预计改造工作量、难度、主要不确定性和建议验证方式。
- 明确建议：采用、仅参考、暂缓或淘汰。

### 6.4 工作量和难度口径

工作量按单人有效开发日估算，不包含等待外部审核、账号开通和用户验收的时间。

| 等级 | 预计工作量 | 典型范围 | 处理建议 |
| --- | ---: | --- | --- |
| S / 低 | 0.5-2 天 | 独立组件接入，接口清晰，少量样式适配 | 可优先复用 |
| M / 中 | 3-5 天 | 需要适配状态、数据或认证，但不改核心架构 | 完成 Spike 后决定 |
| L / 高 | 6-10 天 | 需要替换支付、认证或任务模型，涉及多模块联动 | 与自建成本对比后决定 |
| XL / 很高 | 超过 10 天 | 架构冲突、维护停滞、许可证或安全问题明显 | 原则上淘汰 |

估算报告必须拆分“通用模板改造”和“SpeechOptimizer 业务接入”，防止把一次性业务成本误算成可复用模板成本。

### 6.5 门禁 B：用户选型

用户对每个方向选择以下一种结论：

- 采用候选并进入本地 Spike。
- 仅参考实现，自行开发。
- 补充调研其他候选。
- 暂不实现，移出 MVP。

没有用户决策时，不克隆候选进行大范围改造，也不更换当前技术路线。

阶段交付物：

- 开源候选对比报告。
- 每个候选的改造范围、工作量和难度评估。
- 用户确认的选型记录。
- 通用模板与产品业务的边界清单。

## 7. 阶段 3：Docker 本地环境与核心技术 Spike

### 7.1 目标

只验证会影响 PRD 可行性、范围或成本的关键链路。阶段目标不是完成生产系统，也不是提前部署线上环境。

### 7.2 本地服务原则

应用可根据选定模板以本机进程或容器运行；依赖服务优先通过 Docker 提供。服务清单按实际需要启用：

- PostgreSQL：业务数据、任务状态、权益流水和 Webhook 事件。
- S3 兼容对象存储：只有音频直传和删除验证需要时才启用，候选可在选型阶段确定。
- Redis 或任务中间件：只有选定异步任务方案需要时才启用。
- 本地邮件捕获：只有 Magic Link 或交易邮件流程需要时才启用。
- Mock STT、Mock LLM 和 Mock Waffo：用于稳定复现主流程和失败状态。

外部调用必须明确区分 Sandbox 和 Production；可能产生费用或传输真实用户数据的调用需单独确认。

### 7.3 Spike 1：候选 starter 可改造性

- 在本地启动选定 starter。
- 核对许可证、依赖、项目结构、认证、数据库迁移、测试和 Docker 支持。
- 验证移除无关模块是否会破坏核心能力。
- 验证产品样式与通用模板层能否分离。
- 记录替换内置支付为 Waffo 所需的接口和数据变化，但本 Spike 不要求完成支付。

通过标准：能够明确列出保留、删除、替换和新增模块，且估算误差可控制在一个难度等级内。

### 7.4 Spike 2：录音、上传和音频处理

- 使用固定的 30-120 秒英语样本验证 MP3、M4A、WAV 和 WebM。
- 验证桌面与移动浏览器的录音格式差异。
- 验证真实 MIME、文件大小、媒体时长和失败提示。
- 验证音频写入本地对象存储、短时访问和删除。

通过标准：支持范围、浏览器限制、存储流程和错误边界都有可复现结论。

### 7.5 Spike 3：转写和确定性指标

- 比较至少两个可行 STT 方案，或说明为什么只有一个候选。
- 核查逐词时间戳、置信度、超时、限流和格式支持。
- 用固定样本验证 WPM、口头禅、长停顿、重复短语和句长。
- 记录两分钟音频的估算成本和 P50/P95 处理时长。

通过标准：固定样本可以重复得到误差可解释的指标；目标成本暂定不高于 0.05 USD，硬上限暂定 0.10 USD。

### 7.6 Spike 4：结构化 AI 反馈

- 验证开场、结构、冗余和重复表达的反馈质量。
- 每次最多返回三条按优先级排序的建议。
- 每条建议包含问题、证据、修改方式和重录提示。
- 验证结构化输出失败、超时、内容不安全和低置信输入。
- 找 3-5 位英语使用者私下检查建议是否自然、准确、具体和可执行。

通过标准：固定样本输出结构稳定，不包含无法验证的心理、人格或医疗判断，人工检查意见可追踪。

### 7.7 Spike 5：异步任务和隐私删除

暂定任务状态：

```text
created -> uploaded -> transcribing -> analyzing -> completed
```

任一步骤可进入 `failed` 或 `cancelled`。

- 验证刷新页面后恢复状态。
- 验证超时、重试、取消、重复请求和失败恢复。
- 验证默认删除匿名音频、用户主动保留和删除账户。
- 验证日志不包含原始录音、完整转写或密钥。

通过标准：重复执行不会产生重复任务或重复权益变化；数据库和对象存储的删除结果可核对。

### 7.8 Spike 6：Waffo Sandbox

- 确认主体能否申请和使用 Sandbox/Production。
- 验证 Hosted Checkout 或 Waffo 实际提供的支付流程。
- 验证订阅、一次性支付、取消、退款和失败支付事件。
- 验证 Webhook 签名、重复投递、乱序、重放和事件版本。
- 确认税务、结算、退款、拒付和生产审核责任。

通过标准：能够只依赖验签成功的 Webhook 幂等更新本地订单和权益；无法满足的能力已形成明确阻塞清单。

### 7.9 门禁 C：技术可行性验收

- 选定 starter 或自建方案可以在本地稳定启动。
- 必要依赖均可通过可复现的 Docker 配置启动。
- 录音、存储、转写、确定性指标、结构化反馈和删除链路有验证结论。
- Waffo 的能力边界和阻塞项已确认。
- 关键外部成本、处理时长和数据流已记录。
- 已明确哪些能力进入 P0，哪些推迟到 P1 或移出范围。

阶段交付物：

- 本地环境说明和依赖清单。
- 各 Spike 的输入、命令、结果、失败证据和结论。
- 更新后的技术选型与工作量估算。
- 风险、阻塞和待用户决策清单。

## 8. 阶段 4：形成最终 PRD

### 8.1 PRD 输入

最终 PRD 只使用以下已确认材料：

- 用户确认的产品目标和 MVP 边界。
- 门禁 A 的界面验收结论。
- 门禁 B 的开源项目选型结论。
- 门禁 C 的本地技术验证结论。
- Waffo、隐私、成本和英语反馈质量的已知限制。

未验证内容必须标记为假设、风险或待决策，不能伪装成已经确认的需求。

### 8.2 PRD 必备章节

1. 背景、目标和非目标。
2. 目标用户、核心场景和价值主张。
3. 用户旅程、页面信息架构和交互规则。
4. P0、P1 和明确不做的范围。
5. 功能需求、状态、异常和边界条件。
6. 计费方案、Waffo 事件和权益规则。
7. 数据、隐私、保留和删除要求。
8. 非功能需求：安全、性能、可观察性、可用性和浏览器支持。
9. 技术选型、开源复用边界和 Docker 本地环境。
10. 数据模型、接口边界和异步状态机。
11. 成功指标、埋点限制和验证计划。
12. 风险、依赖、未决项和变更控制。
13. 开发阶段、测试门禁和上线条件。

### 8.3 PRD 完成标准

- 每项 P0 需求都有用户价值、触发条件、正常流程、异常流程和验收标准。
- 页面原型与需求一一对应，没有无需求页面或无界面承载的关键需求。
- 技术选型来自实际调研和 Spike，不使用未经核查的项目能力。
- Waffo、分钟权益、退款、删除和异步任务均有可测试规则。
- 关键数值已确认，或明确标记为实验参数及其验证方式。
- P1 与明确不做的范围清楚，不允许在开发中顺手加入。
- 用户完成最终审阅并确认 PRD 可作为后续开发来源。

阶段交付物：`docs/PRD.md`。该文件只在前三个阶段完成并获得用户确认后创建。

## 9. MVP 待验证需求池

本节保留当前产品需求，供界面原型和最终 PRD 使用；除“已确认约束”外，均可根据验证结果调整。

### 9.1 P0 候选

#### 录音和上传

- 浏览器录音和音频文件上传。
- 暂定支持 MP3、M4A、WAV 和 WebM。
- 客户端快速提示，服务端重新验证真实 MIME、大小和时长。
- 音频不经过长时间同步请求中转。

#### 分析报告

- 总时长、有效说话时长和 WPM。
- 口头禅总数、频率和时间点。
- 长停顿数量、持续时间和时间点。
- 重复短语、句子长度和低置信片段。
- 开头、结构、冗余和重复表达反馈。
- 三条带证据、修改方式和重录提示的优先建议。

#### 重录和比较

- 从结果页立即开始第二次录制。
- 比较语速、口头禅、长停顿、重复表达和结构反馈。
- 区分改善、无明显变化和样本不可比较。
- 不因第二次录音更短而直接判断为改善。

#### 账户和历史

- 匿名用户完成一次基础体验。
- 注册后保存结果和进行前后比较。
- Google OAuth 与邮箱 Magic Link。
- 查看、恢复和删除历史任务。
- 删除单次分析、原始音频和账户。

#### 计费和权益

- Free 分钟、Pro 订阅、充值包和单次深度报告作为待验证组合。
- 分钟预扣、确认、返还、过期和人工调整使用可审计流水。
- Webhook 重复投递不得重复发放权益。
- 取消订阅、退款和失败支付规则与 Waffo 实际能力一致。

#### 最小管理后台

- 查询用户、订阅、分钟流水和分析任务。
- 查看错误和 Webhook 处理状态。
- 重试失败任务、返还分钟和跟踪数据删除。
- 禁用明显滥用账户。

### 9.2 P1 候选

- `filler-word-counter` 独立免费工具页。
- 报告完成邮件通知。
- 更细的练习计划。
- 更多音频格式。
- 存储或 AI 供应商迁移与降级能力。
- SEO 内容页和更完整的运营后台。

### 9.3 明确不做

- 视频肢体、眼神和面部表情分析。
- 实时语音对练。
- 发音纠正和口音消除。
- 多语言分析。
- 团队、学校和企业管理功能。
- iOS、Android 或桌面原生应用。
- Chrome、Zoom 或 Google Meet 扩展。
- 课程、社区和排行榜。
- 复杂可视化编辑器和自动视频剪辑。
- 公开视频案例、AI 伪造评价和虚假社会证明。

## 10. 隐私和安全底线

- 匿名录音默认在分析完成后删除。
- 注册用户默认只保存转写、指标和报告。
- 原始音频只有在用户逐次主动选择后才保存。
- 用户可以删除单次分析、音频和账户。
- 产品埋点和分析平台不得接收原始录音、完整转写或用户表达内容。
- 人工查看转写必须获得用户单独授权。
- 密钥只保存在服务端配置中，不进入浏览器、日志或仓库。
- 上传、回调和 Webhook 需要身份校验、签名校验、限流和幂等保护。
- 任何开源项目进入候选前都要核查许可证、已知安全风险和维护状态。

## 11. 通用建站模板沉淀边界

为了供后续产品复用，通用模板与 SpeechOptimizer 业务必须分层。

### 11.1 通用层候选

- 应用壳、响应式布局、主题和基础组件。
- 认证、账户、角色和权限骨架。
- 数据库迁移、本地 Docker 环境和配置校验。
- Waffo 支付适配边界、订单、订阅和 Webhook 幂等骨架。
- 通用权益流水模型，但不固化“语音分钟”文案。
- 管理后台骨架、审计日志和错误处理。
- 邮件、法律页面占位、测试和开发文档。

### 11.2 SpeechOptimizer 业务层

- 录音、上传、音频格式和时长限制。
- 转写、表达指标、AI 反馈和版本记录。
- 重录比较、报告展示和英语内容规则。
- 语音分析任务、音频隐私与保留策略。
- 具体分钟套餐、价格、运营指标和 SEO 内容。

### 11.3 模板验收原则

- 移除 SpeechOptimizer 业务模块后，通用模板仍可独立启动。
- 新产品可以替换品牌、导航、权益单位和页面，不需要重写认证、支付和本地基础设施。
- 模板有独立的本地启动、升级、测试和安全说明。
- 不把未经验证或只服务单一产品的抽象提前放进通用层。

## 12. 成功指标假设

以下指标保留为私测阶段的首轮假设，最终值由 PRD 确认：

- 至少 50 名非熟人目标用户完成首次分析。
- 首次分析完成率不低于 60%。
- 结果页到重录转化率不低于 25%。
- 7 日再次使用率不低于 15%。
- 至少 5 位非熟人用户真实付费。
- 两分钟分析可变成本目标不高于 0.05 USD，硬上限不高于 0.10 USD。
- 分析任务失败率不高于 5%。

如果重录率低于 15%，优先修复反馈准确性、具体性和可执行性；如果存在重复使用但无人付费，优先验证用户、定价和 Waffo 支付摩擦，不扩大功能范围。

## 13. 粗略工期

工期按单人开发估算，只覆盖“形成最终 PRD”之前的工作，不包含正式 MVP 开发和生产部署。

| 阶段 | 预计时间 | 主要变量 |
| --- | ---: | --- |
| 产品界面与浏览器原型 | 3-5 个工作日 | 页面数量、视觉反馈轮次、移动端调整 |
| GitHub 插件安装与开源调研 | 1-2 个工作日 | 插件可用性、候选数量、仓库质量 |
| Docker 本地环境与技术 Spike | 3-6 个工作日 | starter 改造难度、外部服务账号、Waffo Sandbox |
| PRD 汇总与评审 | 1-2 个工作日 | 未决项数量、需求收缩程度 |
| 合计 | 8-15 个工作日 | 不含等待用户确认和外部审核 |

只有在门禁 C 通过后，才能估算正式 MVP 的开发周期。若某个候选项目被评估为 L 或 XL，应先比较自建成本，再更新总工期。

## 14. 主要风险与处理方式

### 14.1 界面原型与技术能力脱节

- 风险：界面承诺了 Waffo、浏览器录音或 AI 无法稳定支持的能力。
- 处理：界面阶段明确使用 Mock；技术 Spike 后允许回调页面和交互，不把原型当作不可修改的合同。

### 14.2 GitHub 插件不可用

- 风险：无法按指定方式完成实时开源项目调研。
- 处理：停止调研并报告安装或访问问题，等待用户决定是否修复插件或授权替代方式。

### 14.3 开源项目改造成本被低估

- 风险：模板表面功能丰富，但支付、认证、数据模型或许可证不匹配。
- 处理：统一使用候选报告格式；先做最小 Spike；分别估算通用模板和产品业务成本。

### 14.4 Waffo 能力不满足

- 风险：缺少所需事件、Sandbox、主体审核或退款能力。
- 处理：记录为产品或上线阻塞，由用户决定缩减计费模型、等待能力完善或重新调整支付约束。

### 14.5 本地与线上环境差异

- 风险：本地 Docker 通过但生产部署模型不兼容。
- 处理：使用标准协议、迁移和配置边界；本地通过后单独做线上部署评估，不在前置阶段承诺供应商。

### 14.6 英语反馈质量不足

- 风险：确定性指标正确，但 AI 建议泛化、不自然或不可执行。
- 处理：使用固定样本回归、证据绑定、三条建议上限和英语使用者人工 QA。

### 14.7 音频隐私降低使用意愿

- 风险：用户不愿上传含个人声音的数据。
- 处理：默认删除原始音频，在上传前清楚说明用途、保留时间和删除入口。

## 15. 变更控制

以下变化必须更新本计划或最终 PRD，并重新评估范围、工期和验收方式：

- 更换 Waffo 或新增其他支付平台。
- 引入收费 SaaS 模板。
- 新增视频、多语言、实时对练或原生应用。
- 更换主技术栈或引入多个数据库、对象存储、队列实现。
- 修改分钟消费、预扣、返还、过期或退款规则。
- 修改原始音频的默认保存策略。
- 服务未成年人，或增加团队、学校和企业账户。
- 未经技术验证新增会显著影响成本或隐私的数据处理能力。

每次变更至少记录：原因、预期收益、成本、风险、影响阶段、需要重跑的验证和新的验收标准。
